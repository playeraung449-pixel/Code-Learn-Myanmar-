# Lesson Generation & Educational Quality Standards

## 1. MISSION
Generate every lesson using one high-quality educational standard.
Every lesson must teach concepts clearly in Myanmar language while keeping English programming keywords.

---

## 2. LESSON FORMAT (23 REQUISITE SECTIONS)
Every lesson must include:
1. **Lesson Header**: Clear title, course categorization, and estimated duration.
2. **Learning Objectives**: Stated clearly (What to learn, Why it matters, When to use, How it is used in real-world).
3. **Introduction**: Beginner-friendly and welcoming introductory paragraph.
4. **Myanmar Explanation**: Core conceptual breakdown in simple, clear Myanmar language.
5. **English Technical Terms**: A dedicated glossary of keywords that must remain in English (e.g., Variable, Function, Array, HTML, CSS), with their meanings explained in Myanmar.
6. **Theory**: Deeper conceptual or architectural theory behind the topic.
7. **Syntax**: A clean code snippet demonstrating correct, standard syntax structure.
8. **Code Example 1 (Basic)**: A simple, highly understandable code example.
9. **Code Example 2 (Practical)**: A practical, intermediate-level code example.
10. **Professional Example**: An advanced, production-grade example used in real-world systems.
11. **Output Preview**: A console block showing the expected output for the examples.
12. **Common Mistakes**: At least 2 common errors, side-by-side with correct code and explanations.
13. **Best Practices**: Professional tips and guidelines for writing clean code.
14. **Performance Tips**: Performance optimizations or execution efficiency tips.
15. **Security Notes**: Relevant security precautions or defensive programming guidelines (if applicable).
16. **Accessibility Notes**: Relevance to semantic markers, modern accessibility, or safe defaults (if applicable).
17. **Real-world Example**: Description of how this is applied in platforms like Facebook, YouTube, Google, etc.
18. **Mini Exercise**: A code-sandbox style interactive challenge containing instructions, a code template, expected output, and hints.
19. **Quiz**: Exactly 10 multiple-choice or true/false questions, with a passing score of 80% (8/10 correct).
20. **Assignment**: A structured take-home assignment to reinforce the lesson.
21. **Mini Project**: A small project prompt combining previous concepts with a step-by-step guide.
22. **Summary**: A concise recap of the core takeaways.
23. **Next Lesson**: A bridge guiding the student to the next topic.

---

## 3. WRITING STYLE
- Use **Simple Myanmar language** (Unicode-compliant).
- Use **Short paragraphs** and bullet points to increase scannability.
- Provide **Clear, step-by-step teaching** with relatable, everyday analogies.
- Avoid unnecessary academic or dry technical jargon.

---

## 4. TECHNICAL TERMS
All programming keywords, structures, and tools must remain in **English**. For example:
- HTML
- CSS
- JavaScript
- Variable
- Function
- Array
- Object
- DOM
- API
- Database

Always provide the Myanmar translation or explanation of what the term means the first time it is introduced.

---

## 5. CODE EXAMPLES
All code examples must be:
- Correct and runnable without syntax errors.
- Well-formatted and modern.
- Adequately commented where necessary to explain steps.

---

## 6. VISUAL AIDS & CHARTS
Include diagrams, flowcharts, tables, comparison charts, and icons where appropriate to help visual learners grasp abstract programming concepts.

---

## 7. QUIZ RULES
Each lesson must contain exactly **10 questions** comprising:
- Multiple choice questions
- True / False questions
- Code reading questions
- Scenario-based practical questions
Passing score threshold: **80%**.

---

## 8. ASSIGNMENT & MINI PROJECT RULES
- **Assignments** must reinforce the lesson, increase practical skills, and be achievable by beginners.
- **Mini Projects** must combine knowledge from current and previous lessons to build a cohesive functional utility.
